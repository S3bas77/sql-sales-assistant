# SQL Sales Assistant

An AI-powered conversational agent that answers natural language questions about sales data by generating and executing SQL queries against a local SQLite database.

The project uses **Python, SQLite, and Ollama** to transform questions into SQL queries, retrieve real database results, and provide answers in natural language.

## Overview

SQL Sales Assistant allows users to interact with a relational database without writing SQL manually.

Instead of creating queries themselves, users can ask questions such as:

- How many customers are registered?
- Which five customers purchased the most in 2024?
- Which product generated the highest sales?
- How much revenue did each category generate?
- Which products have never been sold?
- Export all sales from 2024 to CSV.

The language model interprets the user's request, generates the appropriate SQL query, and uses the available tools to retrieve or export information.

## Features

- **Natural Language to SQL:** Ask questions in Spanish or other supported languages and retrieve database information.
- **Database Schema Inspection:** Discover available tables, columns, data types, and relationships.
- **SQL Query Execution:** Execute read-only SQL queries against SQLite.
- **Automatic Error Recovery:** Analyze SQL errors and attempt to generate corrected queries.
- **CSV Export:** Export query results to local CSV files.
- **Read-Only Security:** Multiple validation layers prevent database modification.
- **Local AI Model:** Run the language model locally through Ollama, without requiring paid AI APIs.

### Agent workflow

1. The user submits a question through the terminal.
2. The agent sends the question and available tool definitions to Ollama.
3. The model determines the appropriate action and generates a SQL query when needed.
4. The corresponding tool executes the operation.
5. The tool returns the result to the agent.
6. The model interprets the result and generates a natural language response.

The agent can also use database schema information to identify valid tables, columns, and relationships.

## Available Tools

The agent has three main tools.

### 1. `consultar_esquema`

File: `tools/schema_tool.py`

Inspects the SQLite database and provides information about:

- Available tables.
- Column names and data types.
- Primary keys.
- Foreign keys and relationships.
- Number of records in each table.

### 2. `ejecutar_sql`

File: `tools/sql_tool.py`

Executes read-only SQL queries generated by the language model.

It returns:

- Query results.
- Column names.
- Number of returned rows.
- Relevant SQLite errors.
- Warnings when the result exceeds the configured row limit.

If a query fails, the agent can use the error information to attempt a correction.

### 3. `exportar_csv`

File: `tools/export_tool.py`

Exports query results to CSV files stored locally in the `exports/` directory.

Features include:

- Pandas-based CSV generation.
- Automatic file naming.
- Timestamp and unique identifier in generated filenames.
- Absolute file path returned after successful export.

## Database Structure

The project uses a relational SQLite database named `sales.db`.

It contains four related tables:

### CUSTOMERS

| Column | Description |
|---|---|
| customer_id | Customer identifier (Primary Key) |
| name | Customer name |
| email | Customer email |
| country | Customer country |

### CATEGORIES

| Column | Description |
|---|---|
| category_id | Category identifier (Primary Key) |
| category_name | Category name |

### PRODUCTS

| Column | Description |
|---|---|
| product_id | Product identifier (Primary Key) |
| product_name | Product name |
| category_id | Related category (Foreign Key) |
| price | Product price |

### SALES

| Column | Description |
|---|---|
| sale_id | Sale identifier (Primary Key) |
| customer_id | Related customer (Foreign Key) |
| product_id | Related product (Foreign Key) |
| quantity | Number of units sold |
| sale_date | Sale date |

### Relationships

- `SALES.customer_id` → `CUSTOMERS.customer_id`
- `SALES.product_id` → `PRODUCTS.product_id`
- `PRODUCTS.category_id` → `CATEGORIES.category_id`

The database includes fictional sales information from 2023, 2024, and 2025.

Revenue calculations use the following expression:

```sql
SUM(SALES.quantity * PRODUCTS.price)
```

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/sql-sales-assistant.git
cd sql-sales-assistant
```

Replace `YOUR_USERNAME` with your GitHub username.

### 2. Create a virtual environment

```bash
python3 -m venv venv
```

Activate it:

```bash
source venv/bin/activate
```

On Windows:

```bat
venv\Scripts\activate
```

### 3. Install Python dependencies

```bash
pip install -r requirements.txt
```

### 4. Install and configure Ollama

Install Ollama from its official website:

https://ollama.com/

Download the default model:

```bash
ollama pull openbmb/minicpm5:latest
```

Verify the installed model:

```bash
ollama list
```

Ollama normally runs as a background service. If it is not running, start it with:

```bash
ollama serve
```

### 5. Initialize the database

If the database is not already included or needs to be recreated:

```bash
python database/create_database.py
```

This script creates the SQLite database and inserts the sample data.

**Note:** Running this script recreates the tables and their sample records.

## SQL Security

The project implements multiple security layers to ensure that database operations remain read-only.

These protections are implemented in Python and SQLite rather than relying exclusively on language model instructions.

The security mechanisms include:

1. **Read-only database connection:** SQLite opens the database using read-only mode.
2. **Query-only mode:** `PRAGMA query_only = ON` prevents write operations.
3. **SQL validation:** Only permitted read queries beginning with `SELECT` or `WITH` are accepted.
4. **Restricted operations:** Commands such as `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, and other modification operations are blocked.
5. **Single statement execution:** Multiple SQL statements in a single execution are rejected.
6. **SQLite authorizer:** Database-level authorization restricts operations to permitted read actions.
7. **Execution limits:** Query execution is subject to configured row and time limits.
8. **Extension loading protection:** SQLite extension loading is blocked.

The objective is to prevent the agent from modifying or deleting database records, even when a user requests a destructive operation.

## Automatic SQL Error Recovery

The agent includes a query correction mechanism.

When a generated SQL query fails:

1. The execution tool returns the database error.
2. The agent receives the error information.
3. The model analyzes the problem.
4. It attempts to generate a corrected query.
5. The corrected query is validated and executed again.

The correction process is limited to a maximum of three attempts per question.

The agent also performs additional validation against the database schema to help detect invalid columns, tables, relationships, and query structures.

## Testing

The project includes automated tests for the database, tools, security mechanisms, and agent integration.

Run the available tests with:

```bash
python -m unittest discover -s tests -v
```

Integration tests that require Ollama can be enabled with:

```bash
RUN_OLLAMA_TESTS=1 \
python -m unittest tests.test_project.TestIntegracionOllama -v
```

Run the real end-to-end tests with:

```bash
RUN_OLLAMA_TESTS=1 \
OLLAMA_MODEL=openbmb/minicpm5:latest \
python -m unittest tests.test_real_e2e -v
```

These tests can verify functionality such as:

- Database schema inspection.
- SQL query execution.
- JOIN operations.
- CSV export.
- Read-only security.
- SQL error recovery.
- Integration with the local language model.

Some integration tests require an available Ollama service and the configured model.

## Configuration

The application supports the following environment variables:

| Variable | Default value | Description |
|---|---|---|
| `OLLAMA_MODEL` | `openbmb/minicpm5:latest` | Language model used by the agent |
| `OLLAMA_URL` | `http://localhost:11434` | Ollama server address |
| `OLLAMA_TIMEOUT` | `120` | Request timeout in seconds |

To use another installed Ollama model:

```bash
OLLAMA_MODEL=qwen2.5:3b python main.py
```

## Limitations

- The application requires a running Ollama service.
- The default model must be downloaded locally before execution.
- The agent's query interpretation and generated SQL depend on the selected language model.
- The project uses fictional sample data for academic demonstration.
- Query execution is restricted to read-only operations.

## Academic Project

SQL Sales Assistant was developed as an academic Artificial Intelligence project to demonstrate the integration of language models, SQL databases, tool execution, and natural language interaction.

The project explores how an AI agent can interact with structured data through natural language while maintaining database security.
